# VOSR 手机端：NPU / GPU

安装 `vosr-restore-debug.apk`，再导入所需后端的模型包。模型导入完成后，推理无需电脑或网络。

1. 在“推理后端”选择 NPU 或 GPU。
2. 如果提示导入模型，NPU 选择 `vosr-0.5b-htp-v73-models.zip`，GPU 选择 `vosr-0.5b-ncnn-vulkan-models.zip`。两个包不能混用；原桌面 1.4B 模型也不能导入移动端。
3. 选择照片与 2× / 4×，点击“开始复原”。应用保留原始分辨率，切重叠 patch 逐块处理并拼接；块数越多耗时越长，支持取消。
4. 处理完成后对比并保存，图片写入相册 `Pictures/VOSR`。

拍照可直接点“拍照并复原（≥10×）”，在系统相机中设置变焦后拍摄。只有原始 EXIF 的数字变焦记录 ≥10× 才处理；缺失或不足时提示重拍。拍照使用固定 2×，先统一最长边 832、重叠 96 复原，再缩回拍照原尺寸与原始 LR 融合，保存结果仍是原图尺寸。详见 `docs/12-camera-restoration.md`。

NPU 使用 Qualcomm HTP v73，当前针对小米 13 / SM8550。GPU 使用 ncnn Vulkan，两者都是同一套官方 0.5B 单步模型。切换后端时释放旧会话并加载新模型；同一后端后续照片复用已加载会话。应用被系统回收后会重新加载。

小米 13 前台 profile：NPU 单块完整推理中位数 1.588 秒，128×128 输入、4× 输出单块的整次复原约 2.23 秒；GPU 兼容模式单块约 38.55 秒，仍有 134 个矩阵乘法和 85 个归约在 CPU 执行。当前手机建议使用 NPU。GPU 首次会话加载另约 23 秒，大图仍随块数增长。完整计时定义、休眠差异和证据见 `docs/10-performance-profile.md`。

APK 是 ARM64、Android 10+ 的开发签名验证版，已加入默认关闭的详细 profile 入口；模型包无需重新导入。模型和组件许可随本目录提供；生成式复原可能生成原图中无法确认的细节。实际测试与适配范围见 `docs/09-mobile-backend-acceptance.md` 和 `docs/10-performance-profile.md`。

## 电脑侧

项目：`E:\work\ai\aaa-ncnn-vosr`。工具、模型和缓存仍集中于 `E:\work\ai`，不参与手机实际复原。

```powershell
.\scripts\setup-mobile.ps1
.\scripts\build-android.ps1
.\scripts\install-android.ps1 -Backend both
# 仅更新 APK，保留手机已有模型
.\scripts\install-android.ps1 -SkipModels
# 文件和日志验收，不截屏
.\.venv\Scripts\python.exe scripts\test-mobile-backends.py
```

安装脚本使用小米需要的 `--no-streaming`。首次准备 Python 转换环境和官方权重可运行 `scripts/setup-mobile.ps1 -WithConversion`；必要时提供 `-Proxy http://127.0.0.1:7897`。Android GPU JNI 使用 NDK r30，QNN JNI 使用已有 r28。完整构建还需要已安装的 Flutter、JDK 17、Android SDK 和 QAIRT 2.44，默认位置见 `scripts/env.ps1`。

交付文件大小和 SHA-256 见 `SHA256.json`。Git 中只包含源代码、测试、文档和模型清单；APK、大模型和厂商库在本地交付，不嵌入 Git 历史。

手机“下载”目录也保留了 `VOSR-Restore-1.0-debug.apk`、`VOSR-0.5B-HTP-v73-models.zip` 和 `VOSR-0.5B-ncnn-Vulkan-models.zip`，可用于离线重装和导入。
